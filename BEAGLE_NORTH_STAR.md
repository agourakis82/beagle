# BEAGLE North Star

BEAGLE is a personal scientific exocortex: a system for preserving, extending,
and challenging a research mind without flattening it into a generic assistant.

The project exists to protect a particular way of thinking: associative,
interdisciplinary, medically serious, technically rigorous, and willing to
follow unusual hypotheses only when they can be disciplined by evidence.

## Non-Negotiables

- **Preserve the operator's mind.** BEAGLE should remember conversations,
  hypotheses, decisions, drafts, physiological context, and unfinished lines of
  thought as part of one living research surface.
- **Turn accidents into inquiry.** Serendipity is not decoration. The system
  should surface fertile collisions across papers, body signals, agents,
  memory, and domain models.
- **Stay scientifically accountable.** Every ambitious claim should move toward
  evidence, provenance, adversarial review, validation, or publication.
- **Amplify, do not normalize.** BEAGLE should not make the work sound like a
  generic productivity app. It should support the user's own intellectual
  voice, pace, and risk profile.
- **Keep a humane cockpit.** Interfaces should reduce dread and cognitive load:
  small green checks, visible state, resumable work, and clear next actions.

## Product Shape

BEAGLE is not just a chat UI, not just an IDE, and not just a pipeline runner.
It is the coordination layer between:

- long-lived memory and MCP access;
- scientific paper synthesis and publication workflows;
- adversarial agents and self-play review;
- physiological and temporal context;
- knowledge graphs, symbolic constraints, and retrieval;
- exotic hypothesis engines for superposition, interference, hyperbolic
  geometry, paradox, uncertainty, and ontology repair;
- voice, notes, drafts, and daily research decisions.

The UI should make this coordination visible without forcing the user to hold
the whole system in working memory.

## Delegated Science Engines

PBPK is delegated to Sounio in the current architecture. BEAGLE should consume
Sounio outputs as evidence and artifacts, not rebuild that engine internally.

## Recovery Rule

When the project feels too large, recover in this order:

1. **Base green:** `make rescue-check` must pass.
2. **North Star intact:** changes must serve this document.
3. **One living workflow:** improve a real path from thought to artifact.
4. **Only then scale:** add infrastructure, agents, or integrations.

## First Living Workflow

The first workflow to make real is:

```text
thought or voice note
-> memory capture
-> fertile connection
-> adversarial review
-> paper/draft artifact
-> feedback into memory
```

Anything that does not strengthen this loop is secondary for now.

## Design Voice

BEAGLE should feel like a research cockpit at night: quiet, precise, alive, and
close to the work. It can be strange, but it should not be chaotic. It can be
ambitious, but it should always leave one next action visible.
