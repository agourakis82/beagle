# B13.3 Known Limits

## Current limits

- the promotion is scoped to one canonical repo and one active branch/workstream
- the promoted scope covers small and medium Darwin/HPC/Beagle changes, not all
  development at once
- the VM remains available as fallback support; this phase only removes it as
  the mandatory center for the promoted scope
- the proof still uses one canonical operator path and one canonical workflow at
  a time
- the phase does not add new providers, ingress, HA, or broader topology

## Interpretation

B13.3 is about making one bounded development scope officially default through
Beagle/cluster. It is not a global migration of every workflow, and it is not a
new platform phase.
