# Beagle Core — Modernization Plan (2026)

> Gap analysis + prioritized refactor plan. Generated by a multi-agent workflow (21 agents, ~1.2M tokens): per subsystem it mapped the **real repo state** (file:line), researched **SOTA 2025-2026** (literature/web, cited), **adversarially fact-checked** the claims, and synthesized gaps + recommendations. Cross-cutting plan below. Date: 2026-06-04.

## Executive summary

Beagle's core is a genuinely impressive solo-built platform whose biggest risk is not missing capability but a widening gap between advertised behavior and executing behavior. Four independent audits converge on the same root pattern: rich, versioned DTO/schema surfaces and "revolutionary" modules describe hybrid retrieval, cascade routing, multi-agent debate, and IIT consciousness that the runtime does not actually execute. Verified against the code: beagle-memory/engine.rs is 8287 lines with a single dense `points/search` call (no `/points/query`, no RRF) and a stubbed ContextBridge; the named production index (LanceDB ColBERT semantic_memory_v1) is empty and blocked by an mcp->beagle-core 401; the Grok-4-Heavy escalation tier is `grok3.clone()` (router_tiered.rs:297) so the anti-bias lever does nothing; the hot HTTP path computes a limit-aware routing decision then discards it and re-routes, bypassing budgets; the whole beagle-agents crate bypasses TieredRouter via a parallel `AgentLlmClient` trait; migration 001 cannot apply on a fresh DB (zero migrate:up/down markers); prod docker-compose cannot boot (Pulsar hard-required, absent); and brain.rs ships "IIT 4.0 consciousness" with a hardcoded `phi: 0.5` lookup table wired LIVE into the pipeline. The throughline of the fix is the same in every subsystem: make ONE thing real and measured before adding more — one routing brain, one vector source-of-truth, one Phi source, one executing eval gate — then delete or honestly relabel the aspirational scaffolding. The strongest internal asset, the cockpit coord-mcp (SQLite-of-record + Qdrant-derived + nDCG@10 regression gate + verify-before-write), is the proven north-star to port FROM, not rebuild. This plan front-loads correctness bugs and measurement (cheap, unblocking), then consolidation (high-impact), then the genuinely transformational store/router unification, with honesty fixes threaded throughout because they cost almost nothing and de-risk every audit.

## Sequencing (phased rollout)

Phase 0 — Stop the bleeding (days, S effort, low risk): ranks 1-3,5,7,9. Auth/index unblock, double-routing budget fix, migration bootstrap, delete dead triad code, the S-effort correctness batch (Grok key, real/honest Heavy tier, compose healthcheck, Cypher allowlist), ContextBridge stub. These are independent, verified bugs/footguns with no dependencies; ship them as small reviewable PRs first so the platform is correct before anything is built on it. Phase 1 — Make it measurable (1-2 weeks, M effort, low risk): ranks 4 and 6. Stand up the executing eval+regression gate and measured token usage. NOTHING in later phases ships without passing through this gate. Phase 2 — Make one of each thing real (2-4 weeks, M effort): ranks 8,10,11,15. Real hybrid+RRF retrieval and reranker discipline (gated by Phase 1), agents onto the unified router trait, one honest Phi source, first-class calibrated verification. Phase 3 — The two transformational consolidations (4-8 weeks, L/XL, high risk, staged behind flags + dual-read/dual-write windows, old stores read-only until parity proven on the eval gate): rank 12 (single canonical memory store) then rank 13 (single router) then rank 14 (caching on the unified gateway). Phase 4 — Hardening, hygiene, and targeted research adds (ongoing, opportunistic): ranks 16-22. engine.rs split and context.rs/merge_config refactors (behavior now locked by tests), Pulsar-optional + queue/graph consolidation, quarantine the aspirational crates, the isolated axum 0.8 PR, GraphRAG/tournament/checkpoint research lanes, and the batched dependency/OTel/docs/k8s housekeeping folded into whichever feature PR touches the same area. Golden rule throughout: one correctness/honesty fix per area before any new capability, and no consolidation merges until the eval gate proves parity.

## Big bets (transformational)

- Executing eval+regression gate across the Rust stack (nDCG@10/Recall for retrieval, cost-quality logs for routing): the keystone that turns every other change from 'vibes' into a measurable win/loss and gates the risky consolidations (rank 4).
- Single canonical memory store: Postgres/SQLite system-of-record + one rebuildable vector projection, demoting the other three of four uncoordinated stores to derived/optional — the cockpit pattern as the platform north-star (rank 12).
- Single routing brain: collapse TieredRouter + SmartRouter into one gateway with real budget enforcement, resilience (breakers/fallback/rate-limit), first-class self-hosted LiteLLM/vLLM fleet, and one cache point (ranks 10+13+14).
- Honest cognitive surface: one real Phi source (phi_iit) feeding both pipeline and HTTP, aspirational consciousness/quantum/qualia crates quarantined behind feature flags, neurosymbolic verify-backed loops replacing measurement theater (ranks 11+15+19).
- 5-stores-to-2 data-layer consolidation (pgmq for queue, Apache AGE for graph, pgvector for vectors, Redis for cache only) — the highest-effort/highest-payoff infra simplification, staged behind flags with dual-read windows (rank 18).

- REFRAME Grok-4-Heavy escalation tier — it is grok3.clone() (router_tiered.rs:297) selecting the same model as default; the anti-bias 'vaccine' gives zero uplift. Either make it a genuinely stronger model id or rename the tier honestly.
- REFRAME 'hybrid retrieval' in beagle-memory — all sparse/RRF machinery is DTO plumbing (sparse_backend literally 'local-lexical', one points/search call). Either implement real RRF via /points/query or stop advertising hybrid in the schema.
- REFRAME 'adversarial debate' triad branding — the live run_triad is a strictly linear ATHENA->HERMES->ARGOS->Judge chain with no debate/rebuttal/consensus; verified evidence is AGAINST naive debate. Rename to 'linear adversarial review' until/unless a real evolve loop is added.
- DROP fabricated doc-comment metrics ('p50=1.2s / 92% alignment / N=100') and named-researcher citations dressing up dead code — audit liability with no backing benchmark.
- REFRAME the Rust<->Julia PCS symbolic integration — generate_symbolic_summary is a keyword-heuristic TODO stub fed into the live ARGOS/Judge prompts as if real. Either wire the real Julia seam or stamp output 'heuristic, not solver-verified'.
- REFRAME the LanceDB+jina-colbert-v2 'production index' claim — it is row_count:0 / index_ready:false platform-wide; do not call it production until rank 1 populates it.
- FIX docs that describe non-existent reality: root CLAUDE.md calling beagle-memory the RAG home (runtime moved to exocortex/cockpit Qdrant), beagle/CLAUDE.md's wrong BeagleContext struct + path, and BEAGLE_ROUTER_IMPLEMENTATION.md placing TieredRouter in the wrong crate.
